# Contributing

Thanks for helping improve this playbook. Small fixes and new entries are both welcome.

## How to propose changes

- Open an issue to discuss a new topic or a larger rewrite.
- Or open a pull request against `main` with your change. Keep each pull request focused on one entry or one fix.

## Content guidelines

- Keep answers accurate, concise and practical.
- Prefer vendor-neutral wording, and name tools by their current names.
- State versions or dates when a claim may age, for example "as of 2026".
- When you add an entry, add it to the Table of Contents in `README.md`.
- Heading anchors are generated from heading text. If you rename a heading, update its Table of Contents link too.

## Markdown style

- Use one H2 (`##`) heading per entry, in sentence case, matching the existing entries.
- Put code in fenced blocks with a language tag, such as `yaml` or `bash`.
- Remove trailing whitespace before you commit.

## Commit style

Use [Conventional Commits](https://www.conventionalcommits.org/) with a one-line subject, for example:

```text
docs: update GitOps entry
```
